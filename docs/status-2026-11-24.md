## 2. What was built

**The tool.** `pmdshodh` scores ancient DNA reads for post-mortem damage with the PMDtools model (Skoglund et al. 2014). It was built from the paper and black-box tests only, without PMDtools' source. It has five commands:
- `filter`: keeps reads above a PMD threshold and writes BAM or SAM;
- `score`: writes per-read scores;
- `damage`: writes damage tables and a JSON run summary;
- `report`: turns run summaries into an HTML damage report;
- the PMDtools option names, which are accepted throughout, for a drop-in swap.

**The run summary.** A versioned JSON summary, now at `format_version` 4, records every count, skip reason, damage table and setting. MultiQC reads it, and so does `report`. Identical runs give identical files.

## 3. What was fixed and improved

**PMDtools behaviours corrected by default.** `--pmdtools-compat` reproduces each of them exactly (README, Compatibility):
- **7 that change scores:** for example, the reference rebuilt wrongly around indels with clips, CpG context wrapping around the read ends, `--ss` counting each C site twice, and reverse-strand MD shifts that inflate scores by up to 15.7.
- **10 that crash or lose data silently:** for example, reads without MD dropped silently, MD from MALT misparsed, hard-clipped and 1-base reads dropped, crashes on `DS:Z` tags, header-only input, long reads and `--first`, and truncated BAMs passed on silently.

**pmdshodh's own bugs, found by audits and fuzzing:**
- **0.2.1–0.2.4:** truncated BGZF input and `=` bases without `-r` became input errors. Outputs no longer replace FIFOs, devices or the input file. A closed stdout ends quietly. Temporary files are removed on Ctrl-C. Duplicate CG tags were fixed.
- **0.3 audit (docs/audit-0.3.md), B1–B10, all fixed in 0.3.1–0.3.3:**
  - a stale FASTA index gave wrong reference bases (B1);
  - an absurd CIGAR was costly before failing (B3);
  - compat mismatches with PMDtools on unmapped-but-aligned reads and 1-base reads (B4, B8);
  - a corrupt CRAM could allocate up to 2 GB, found by the CRAM fuzz target (B10);
  - and others.
- **After 0.3.3 (on `main`, unreleased):** a CRAM cut inside its header now says where it ends, and `score -o -` leaves stdout empty when the first reads fail.

**Checks that now exist:**
- **Read-by-read parity:** against PMDtools on the nf-core/eager test BAMs, five real libraries (ds untreated, ds UDG-half, ds full UDG, ss untreated, ss USER-treated) and the output of bwa, bowtie2 and samtools.
- **Damage tables:** identical to `pmdtools --deamination` at all 30 positions.
- **Property and fuzz testing:** 10,000 property cases and a CRAM fuzz target, with a clean hour of fuzzing after B10.
- **The damage-curve study:** a read simulator and an exact-likelihood ceiling (tests/sim). On ds libraries, the default score is within 0.3–4.3 percentage points of the best any damage curve can do. Fitting the damage parameters gains about 1 point, so it was not implemented. For untreated ss libraries, `--pmd-c 0.05` kept 3–4 points more ancient reads on real reads, which the README now documents.

## 4. Where it stands

- **Status: alpha** (README). The scores are validated read by read, but no outside user has reported on the tool yet.
- **Released:** 0.3.3 on GitHub and PyPI. Bioconda's bot bump to 0.3.3 (bioconda/bioconda-recipes#72119) passes its checks and waits for a Bioconda member's review.
- **On `main`, unreleased:** the CRAM header and `score` stdout fixes, the study and the README note.
- **Integration:**
  - **MultiQC:** module PR MultiQC/MultiQC#3745 and test data MultiQC/test-data#406 are open; CI passes except the two tests that need #406 merged, and neither has a maintainer review yet.
  - **nf-core:** the `pmdshodh/filter` module is built and passes nf-core lint (67 checks) and nf-test (4 tests) locally. It is not submitted; it waits for Bioconda 0.3.3, so that it can pin it.
  - **nf-core/eager:** a proposal follows once the nf-core module is accepted.
